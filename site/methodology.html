Methodology and verification

How the "verify everything, never infer" rule was enforced by code rather than by assertion.

The rules this project was built under, and how each was enforced mechanically rather than by assertion.

Rules applied

RuleHow it was enforced
Every table row must have a source link to an official site All content is rendered from data/*.json by tools/build.mjs. The renderer has exactly two possible outputs for a source cell: a real link to an official document, or the literal badge "UNVERIFIED — no official source". There is no code path that emits an empty source cell.
If a value cannot be confirmed from an official source, leave it blank and flag it Unconfirmed fields hold the literal string unverified in the JSON. The renderer converts that string into a visible red UNVERIFIED badge rather than printing a number. tools/verify.mjs fails the build if a field is empty or whitespace-only instead.
Never infer or fill in values No figure on this site is derived from a commercial or advisory source. The only sources in data/sources.json are irs.gov, fincen/cbp.dhs.gov, loc.gov, safe.gov.cn, pbc.gov.cn, chinatax.gov.cn and english.www.gov.cn.
Verify line by line from primary sources Each source carries verifiedByFetch. A true value means the page was retrieved during this session and the supporting sentences were read on it. A false value is downgraded to "search-index" everywhere it appears and is repeated on the Flagged for Review page.
Flag irregularities for review 16 flags are recorded in data/flags.json and published on the Flagged for Review page, including three that record gaps in this project's own evidence base.

The verification command

node tools/verify.mjs runs after every build and fails non-zero if any check breaks. It checks:

1. Every JSON data row carries a resolvable source id whose URL is present and starts with https:// or http://, or the row is explicitly marked unverified.
2. Every rendered tr.data-row in the built HTML contains at least one anchor to an external official source, or contains the UNVERIFIED badge.
3. No internal href points at a file that does not exist in site/.
4. No anchor fragment points at an id that does not exist in the target page.
5. No data field is empty or whitespace-only — a blank cell is a build failure, because a blank cell and an unverified cell are different claims.
6. Every source URL is on an official allowlist domain.

What was not verified, and why

Outbound HTTP from this build sandbox is restricted to a small allowlist that does not include irs.gov or safe.gov.cn, so external links cannot be re-requested at build time. External URL verification was therefore performed during research, in-session, page by page, and the result is recorded per source in the source register. Internal links and fragments are checked mechanically on every build, because those are the links this project controls.
