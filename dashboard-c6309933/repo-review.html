Repository review

Line-by-line findings from reviewing this repository, each with the command that produced it.

Method Every finding below came from a command run against the checked-out tree in this session, not from reading prose. Where a finding was later disproved it is recorded as resolved rather than quietly dropped — see R02.

Findings

R01 · The ladder CI check is date-dependent and will fail on any day after the last regeneration   medium needs review

Evidence: ladder/model.py line 908 sets `generated=date.today().isoformat()`. .github/workflows/verify-ladder.yml line 28 runs `git diff --exit-code -- ladder index.html`. Reproduced in this session: running `python3 ladder/model.py && python3 ladder/build.py` on 2026-11-11 changed 12 committed files (12 insertions, 12 deletions), the only change being `"generated": "2026-11-10"` -> `"generated": "2026-11-11"` in ladder/data/meta.json and the same date echoed into 11 generated pages. Local changes were reverted with `git checkout -- ladder/`; ladder/ is owned by other sessions.

Why it matters: The check currently passes only because PR #62 regenerated the ladder on 2026-11-11. On 2026-11-12 the identical tree will fail `verify-ladder` with no code change.

Recommendation: Derive `generated` from a value committed in the tree (e.g. `git log -1 --format=%cs -- ladder/data/meta.json`) or exclude the `generated` key from the diff check.

R02 · audit-92d12752/verify.py snapshot assertion - previously failing, now passing   low resolved - no action

Evidence: On the base commit 30ea791 this session ran `python3 audit-92d12752/verify.py` and it raised `AssertionError: snapshot differs: rerun build.py after inspecting repository changes`. Why it matters: Recorded so the correction is on the record. This is NOT an open defect on current main.

R03 · Twenty separate published sites in one repository, with overlapping and non-identical figures   high needs review

Evidence: `find . -name index.html -not -path './.git/*' | wc -l` returns 20: acceptance-373b54a3, acceptance-a64bd476, audit-0f0f59fe, audit-456e7542, audit-6068a908, audit-86f0, audit-92d12752, audit-ad300459, briefing, docs, estimate-facf2fe9, final-f6327e23, the repository root, ladder, portal, repatriate, site, study-8f529c94, verify-88f5a1be, verify-d5d1f860. Each publishes its own cost tables. The published row counts differ by site: ladder 600 rows / 20 routes, repatriate 680 rows / 17 methods, study-8f529c94 920 rows / 23 methods, estimate-facf2fe9 920 rows / 23 methods, briefing 680 rows / 17 methods, verify-d5d1f860 680 rows / 17 methods, audit-86f0 880 rows / 22 methods.

Why it matters: A reader landing on the site cannot tell which table to trust, and two tables for the same corridor give different totals because they make different assumptions about the FX spread. This is the single largest usability defect in the repository.

Recommendation: Retire all but one canonical dashboard and replace the rest with redirects, or clearly label each as a historical snapshot with a date and a pointer to the canonical one.

R04 · PRC individual income tax rates are published across the repo but were NOT verifiable from an official source in this session   medium needs review

Evidence: The root README.md asserts `3%-45%` comprehensive IIT, `5%-35%` business IIT and `20%` flat asset/dividend/interest IIT. This session attempted to verify them from the State Taxation Administration statute database and from www.gov.cn. The chinatax.gov.cn fetch failed and https://www.gov.cn/xinwen/2018-09/01/content_5318220.htm now redirects to the gov.cn homepage, returning no statute text. NO PRC rate is therefore published anywhere in dashboard-c6309933; every PRC tax cell is BLANK.

Why it matters: The rates may well be correct, but they are not currently traceable to a live official page, and the brief requires an official source link per row.

Recommendation: Re-point those citations at a currently resolvable official URL (for example the STA law database at fgk.chinatax.gov.cn) and re-fetch before publishing the figure.

R05 · Insecure http:// links to official PRC sources across the repository   medium needs review

Evidence: `grep -roh 'http://...'` over tracked .md/.html/.json files returns at least 17 distinct http:// official URLs, including http://m.safe.gov.cn/safe/2021-07-02/19307.html, http://www.safe.gov.cn/en/2017/1230/1397.html, http://english.customs.gov.cn/... and http://www.customs.gov.cn/. Two are malformed placeholder strings (`http://` and `http://...`) and one has a trailing full stop (`http://m.safe.gov.cn/safe/2004-1116/5461.html.`).

Why it matters: A citation that does not resolve is not a citation. Placeholder and trailing-punctuation URLs are unambiguously broken.

Recommendation: Convert to https://, delete the two placeholder strings, and strip the trailing full stop. Note that dashboard-c6309933 deliberately cites the https form where one resolved; S11 could only be resolved over http and is labelled accordingly.

R06 · Eight competing executive summaries with no single authoritative one   medium needs review

Evidence: `find . -iname '*EXECUTIVE*SUMMARY*'` returns 10 files: EXECUTIVE-SUMMARY.md, EXECUTIVE_SUMMARY.md, briefing/EXECUTIVE_SUMMARY.md, docs/executive-summary.md, repatriate/EXECUTIVE_SUMMARY.md, reports/EXECUTIVE_SUMMARY_85f37d08.md, research/EXECUTIVE_SUMMARY.md, research/previous-dashboard/EXECUTIVE_SUMMARY.md, site/executive-summary.html, study-8f529c94/EXECUTIVE_SUMMARY.md. The root README links only some of them.

Why it matters: The brief asks for one executive summary. Ten files with different conclusions means none of them is the answer.

Recommendation: Designate one file as canonical, reduce the others to a single-line pointer, and update the README.

R07 · The task board has grown to a size where it no longer prevents collisions   low needs review

Evidence: COORDINATION.md is 984 lines / 179,707 bytes. It records at least three collisions the board did not prevent: COORDINATION.md add/add conflicts on three separate merges, two sessions claiming the same root hub (arena/4decd480 and arena/d5d1f860, pushed 57 seconds apart), and one session's package.json `"type": "module"` field breaking another session's CommonJS test.

Why it matters: A 180 KB append-only log cannot be read before claiming, which is the mechanism the brief relies on.

Recommendation: Split it: keep a short machine-readable claims table (task, owner, scope, timestamp, status) at the top and move the narrative logs into per-session files.
